# 结果输出与实验有效性

## 1. 模型、参数、结果三部分

默认使用 `summary` 模式，输出模型、参数和结果的精简报告；
也可通过 `--stats-view summary` 显式选择。
终端统一使用英文标题 `MODEL / PARAMETERS / RESULTS` 和英文指标标签，
用户自定义名称原样保留；中文只用于文档说明。JSON 使用独立的机器字段和单位。

内容仍分为三部分：

- 模型：类型、Channel/PC/SID 或 Subchannel/Rank 组织、Bank/行列、计算容量、请求粒度和工作规则。
- 参数：接口速率、时钟、负载、队列容量，以及相对程序内置基准的参数变化摘要。
- 结果：完成性、时间、吞吐量、读事务延迟、行命中率、检查结果；能量和温度按启用状态附加。

HBM 的中性 Rank=1 不单列；非 1 的实验 Rank 会显式提示，不能隐去影响容量的维度。
LPDDR 使用器件/Subchannel/Rank 标签。组织打印的是逻辑寻址层级，不把 SID 等同于一颗物理 die。
单控制器验证模式额外警告：配置组织容量不表示实际模拟了全部 Channel。

容量采用实际组织计算，标称 density 不参与替换：
`capacity_per_instance_bytes = channels × pseudo_channels × sids × ranks × bank_groups × banks_per_group × rows × columns × dram_transaction_bytes`。
系统容量再乘实例数。当前配置入口和模型校验拒绝密度与几何折算值矛盾的输入；
报告层仍保留防御性 WARNING，用于不一致的外部结果对象，而不是正常配置的放行机制。
HBM 按 stack_height 归一，LPDDR 按 channels × pseudo_channels × ranks 归一，
与配置推导共用计算函数，正常 LPDDR6 不应出现密度 WARNING。
GiB 是 2^30 Byte；标称 Gb 在这里按 2^30 bit 的组织口径核对。
后端分配字节是数据行记账，不是进程 RSS 或磁盘实际占用。

典型使用：

```bash
mkdir -p outputs/result_example
./build-clang-debug/hbm_sim --config configs/hbm.cfg --standard hbm4 \
  --requests 128 --stats-json outputs/result_example/result.json \
  --dump-resolved-config outputs/result_example/resolved.cfg \
  | tee outputs/result_example/summary.txt

python3 tools/view_stats.py outputs/result_example/result.json \
  --keys standard,host_requests,dram_transactions,simulation_time_ns,achieved_bw_GBps,avg_read_latency_ns
```

summary.txt 用于人读，不是机器键值接口。可视化的 `--stats` 和工具输入应使用 result.json。
不要用 `rg '^system_cycles' summary.txt` 判断指标丢失。
交付手册中的普通运行同样遵守这一约定：同名 `stats.txt`/`stats.json` 分别供人读和工具读取，
普通运行无需开启诊断模式。专项诊断单独见
[交付手册 7.1.2](../堆叠存储模型交付手册.md#section-7-1-2)，其完整输出保存到独立文件，
不混入普通性能结果；字段缺省不等于零。命令行 `--stats-view diagnostic` 会覆盖
配置里的 `stats_view=summary`；该模式仅用于专项诊断。
机器结果按语义分区，metrics 只保存公共运行指标；完整复现参数保存在 resolved.cfg，
命令/DFI/数据/热图仍由相应的导出选项产生，结果 JSON 不会自动启用这些轨迹。

## 2. 参数变化比较的基准

比较对象是**当前程序内置的同标准模型（按配置 schema 3 解析）及 CLI 默认选项**，
不是修改后的配置文件自己，也不是 JEDEC 或厂商认证型号。终端和 JSON 都记录该基准名称。

比较实际生效的 resolved 参数，因此直接修改 [standard.*.organization] 或 Timing 段也能发现。
基本负载、请求数和已显示的参数无需重复罗列；不因 [override] 是否出现而决定有没有变化。
同一 Timing 数值从 jedec 标签改成 vendor 不算数值变化，来源仍由 resolved.cfg / Timing 表审计。

终端最多列两条尚未在结构摘要中体现的变化（优先 Timing），并明确总数；JSON 的 changes 保存完整比较清单。
变化值包含自动推导的结果，不声称每项都是用户直接输入。例如改 columns，
容量和几何折算 density 会同时变化。内置基准和主模板存在有意的队列/PHY 默认差异，
因此未改模板也可能有变化记录，这不代表配置错误。

比较清单不替代配置来源审计。`--dump-config-diff` / `--compare-preset`
采用配置层对比口径，不等同于结果中的内置基准比较。
运行复现应保存完整配置、resolved 快照及源码/二进制版本；改变程序版本可能改变内置基准。

## 3. JSON schema 2

配置 schema 与结果 schema 是两个独立版本。结果由 C++ 类型化值直接序列化，
精度独立于终端展示时的四舍五入。

| 分区 | 内容 |
| --- | --- |
| schema_version / run_status / error | 格式版本，以及 completed / truncated / failed 和错误信息 |
| model | 实际模型身份、组织、规则、启用状态，不算性能指标 |
| parameters | 本次接口和负载的关键参数 |
| metrics | 下面列出的精简运行指标，不重复配置 |
| validation | 命令/DFI 状态及检查量、数据检查/错误量、ECC 不可纠正错误量；执行 Golden 验证时附加检查量 |
| comparison_baseline / changes | 比较基准及完整有效值变化列表 |
| stacks | 每实例完成读写数、带宽、平均读事务延迟，用统一列结构表达 |
| diagnostics | 仅显式 diagnostic 模式附加，不是公共指标契约 |

metrics 的固定候选集合如下；未启用的功耗/热字段不生成：

| 字段 | 单位与含义 |
| --- | --- |
| host_requests | 成功接收的 Host 请求数，不是完成的 Host 响应数 |
| dram_transactions | 拆分后的提交事务数 |
| completed_reads / completed_writes | 完成的 DRAM 事务数，包含相应的转发/合并完成路径 |
| remaining_requests | 排队/未注入的混合工作量，可能含维护请求，不能解释成纯 Host 数 |
| remaining_pending | Controller pending 完成项；与 remaining_requests 分开 |
| hit_cycle_limit | 因周期上限而未完成 |
| system_cycles / simulation_time_ns | 系统 tick 数 / 物理仿真时间，不累加 Controller 周期 |
| read_bytes / write_bytes | 完成事务的 payload 字节数 |
| achieved_bw_GBps | 十进制 GB/s，有效 payload 吞吐量 |
| peak_bandwidth_GBps / bandwidth_util_pct | 理论峰值 / payload 吞吐占峰值百分比 |
| avg_read_latency_ns | 平均读事务延迟，非 Host burst 重组延迟；没有完成读时为 null |
| row_hit_pct | hits / (hits + misses + conflicts) × 100；无分类请求时为 null |
| storage_lines_allocated / storage_bytes_allocated | 后端分配行数 / 该层的数据字节记账 |
| power_energy_pJ | 启用功耗模型时的累计能量 |
| thermal_avg_temp_C / thermal_peak_temp_C | 启用热模型时的平均/峰值温度 |

行访问在请求首次参与调度时分类一次；它不是后端 rowbuf_hits 的命中率，
分母也不必等于 Host 请求数或所有完成事务数。

物理时间换算：tick_duration_ps = tCK_ps / tick_multiplier；
simulation_time_ns = system_cycles × tick_duration_ps / 1000；
平均读事务延迟同样从其 controller tick 口径换算。
这是模型时间，不是仿真程序的墙钟耗时。DVFS 使用当前模拟器的时间记账口径，
该结果不是逐段变频时钟积分。

## 4. 检查状态与失败结果

- 命令/DFI 检查未启用是 not_run，不是 pass。
- data_checked_reads=0、data_mismatches=0 不构成独立数据正确性证据。
- DFI 结构自洽不等于请求提供独立 expect 的数据验证。
- 没有读事务时延迟 null；未启用功耗/热模型时字段缺省，不能当成零测量。
- ECC 不可纠正错误和容量不一致不会因为精简而被静默隐藏。
- truncated/failed 不允许无标记进入有效性能曲线。

已确定结果路径后、执行开始前，指定 JSON 先写为未完成的失败状态；
成功结束后替换。后续输出异常会把最终状态设为 failed，不保留成功状态副本。
参数解析失败可能尚未确定路径，所以**首先检查进程退出码**，不要只读取旧文件。

实验工具还要求：未达周期上限、remaining 两项为零、无数据不匹配、
完成读写之和等于 dram_transactions、所需字段存在且类型和数值有效。
这些条件不证明厂家准确性；性能比较仍需相同 trace/seed、地址域、后端、
调度策略及实际时序。固定 requests/tick 与固定 requests/ns 不是同一负载口径。

## 5. 专项诊断与工具读取

需要检查 PHY FIFO、维护、数据后端、响应导出或 Timing 来源时，显式请求：

```bash
mkdir -p outputs/result_audit
./build-clang-debug/hbm_sim --config configs/hbm.cfg --standard hbm4 \
  --requests 128 --stats-view diagnostic \
  --stats-json outputs/result_audit/result.json \
  > outputs/result_audit/diagnostic.txt

rg '^(phy_command_backpressure|data_checked_reads|host_responses_exported)\s*:' \
  outputs/result_audit/diagnostic.txt
```

diagnostic 保留专项验证确实使用的内部计数和配置键；它不是另一份默认公共指标。
其键排序输出，不能依赖固定行号。JSON 中 diagnostics 也是显式选择才附加。
内部事件计数仍可用于 C++ 测试，不为了输出变短而破坏模型运行或验证。

需要 bytes/tick 时，用 payload 字节数除以 system_cycles。队列平均占用在诊断中
使用 *_q_avg_per_ctrl，分母为 aggregate_ctrl_cycles。
Host/transaction、控制器/后端行命中、payload/interface 带宽具有不同语义，不能互相替代。
接口速率专项校验使用 if_xfer_rate_Gbps。

程序应按 model/parameters/metrics/validation 分区读取 JSON，或调用 tools/result_io.py。
项目读取器接受诊断键值文本、JSON schema 1 和 schema 2，提供供分析工具使用的平面视图。
其中 avg_read_latency 按 ns 换算回 tick；公共 JSON 的 avg_read_latency_ns 在无读请求时为 null。
读取器的 tick 延迟辅助字段在无读时为 0，使用时必须同时判断 completed_reads。
缺失必需指标会报错；人读摘要不能用作机器结果。整数计数不经浮点转换。

普通可视化、性能曲线和敏感性分析读取公共结果，不要求诊断字段。
性能曲线文件的 avg_read_latency_ticks 明确使用 tick 单位，row_hit_pct 使用百分比；
曲线格式与模拟器结果格式是独立接口。敏感性实验仅在启用功耗/热模型时输出能量和温度，
字段缺省不能解释成零测量。
