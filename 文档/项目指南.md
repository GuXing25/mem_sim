# hbm_sim 项目指南

本文档是 `hbm_sim` 的详细使用和代码说明。根目录 `README.md` 更像项目入口和能力概览；本文档更像开发手册，重点回答四个问题：

1. 这个项目整体做什么。
2. 用户如何构建、运行、配置和验证。
3. 输出结果中每一类字段代表什么。
4. 每个代码文件大致负责什么，后续修改应该从哪里入手。

JEDEC 固定或推导数据、真实厂商数据和研究默认值的字段边界见
[审计](审计.md)；同一文档后半部分给出项目原生证据、验收阈值、DFI 正反例和
Ramulator2.1 外部参考边界。进行 HBM4/LPDDR6 数值实验前，应检查其中的来源标签。

## 当前实现快照

本手册已同步到当前代码版本：CLI 默认使用流式请求源；trace 支持普通 `R/W`
和突发 `BW/BR`；真实存储区由 `MemoryImage + MemoryBackend` 组成；后端支持
`sparse`、`mmap_sparse`、`chunk_file`；读写正确性同时比较数据和逐字节
初始化标记；物理模型覆盖 channel、pseudo-channel、SID、bank、row、column、
tile、grid、subarray、mat、cell、microbump 派生坐标。DFI 输出是 beat/signal
级 CSV；事件结构做离线自洽检查，请求提供 `expect=` 时再独立检查读数据。

大容量存储后端的选择策略见 [多 Stack 及存储后端](多Stack及存储后端.md)，本文不重复展开。

## 1. 项目概括

`hbm_sim` 是一个面向 HBM/LPDDR 控制器研究的小型 C++ DRAM 模拟器。它的定位介于两者之间：

- 架构上选择性借鉴 Ramulator2.1 的 memory system、controller、scheduler、row policy、refresh/RFM manager、timing engine 和 command trace 分层；模型裁决仍以 hbm_sim 项目需求和自身验证为准。
- 建模对象上聚焦 HBM3、HBM4、LPDDR5、LPDDR6：不追求 DDR/GDDR/PCM 等全标准覆盖，代码规模比 Ramulator2.1 更小。
- 数据目标上尽量靠近 JEDEC/vendor：支持 timing table、timing source、speed-bin、density、stack-height、mode、vendor profile 等字段，但当前仍有研究默认值，需要在真实器件对比前继续填入目标手册或厂商表。

项目适合做这些工作：

- 对比 HBM3/HBM4/LPDDR5/LPDDR6 的访存行为。
- 研究 controller 调度策略、row policy、地址映射、refresh/RFM 策略对带宽和延迟的影响。
- 评估 HBM row/column 双总线、HBM edge pairing、LPDDR WCK/CAS、DVFS、DBI/ECC/link protection 对接口利用率的影响。
- 生成 command trace，并用离线 validator 检查命令语义、timing、bank 状态、HBM edge pairing 和 LPDDR WCK 窗口。
- 提供 DFI 6.x-oriented Behavioral PHY 与 beat/signal trace，把命令和真实 PHY completion 转为 `COMMAND`、`READ_DATA`、`WRITE_DATA` 事件，并导出 enable、address/bank、mask、真实 request/MemoryImage payload 等字段。

当前项目已经具备标准化框架和大量协议入口，但真实数值级对比还需要继续填充完整 vendor timing table、完整 mode register 语义、ECC/RAS 错误流程和 golden trace 对比体系。

## 2. 总体架构

项目按职责分层：

```text
hbm_sim
  configs/             实验配置和 timing profile 片段
  examples/            示例运行脚本和 trace
  include/hbm_sim/     公共头文件
  src/                 C++ 实现代码
  tests/               smoke test 和 sequence test
  tools/               辅助脚本
```

核心运行路径如下：

```text
CLI/config
  -> DramSpec preset/profile/override
  -> Traffic frontend 生成 Request
  -> MemorySystem 按 channel 分发请求
  -> Controller 调度 request buffer
  -> CommandState 判断命令状态合法性
  -> TimingEngine 判断 timing 是否 ready
  -> CommandExecutor 执行命令副作用
  -> Stats 汇总结果
  -> CommandTrace/Validator 可选导出和验证命令流
```

各层职责：

- `cli`：解析命令行和配置文件，创建一次仿真实验。
- `frontend`：产生请求，包括 synthetic traffic、trace、初始化/训练控制序列。
- `core`：地址映射、多 controller memory system 和基础类型。
- `dram`：标准 preset、timing table、JEDEC 换算、命令语义、命令状态、接口开销。
- `controller`：请求队列、调度、row policy、refresh/RFM、timing gate、命令执行。
- `stats`：统一统计字段和文本输出。
- `validation`：命令 trace 导出和离线命令流验证。

```

```

```bash
make test
```

### 3.4 trace 输入

trace 支持两种格式：

```text
R ADDRESS
W ADDRESS
CYCLE R ADDRESS
CYCLE W ADDRESS
W ADDRESS data=HEX
R ADDRESS expect=HEX|last_write
W ADDRESS data=HEX mask=HEX
BW ADDRESS len=BYTES pattern=request_id|zero|ff
BR ADDRESS len=BYTES check=last_write|auto|request_id|zero|ff
```

示例：

```text
# read address 0x1000
R 0x1000
W 0x2000
100 R 0x3000
120 W 0x4000
```

运行 trace：

```bash
./build/hbm_sim --standard lpddr6 --trace examples/sample.trace --requests 0
```

说明：

- `--requests 0` 表示读取完整 trace。
- trace 模式下，`--requests N` 限制的是展开后的请求数；一个 `BW/BR len=512` 在 64B line size 下计为 8 条请求。
- 两列 trace 会按 `--inject-interval` 自动生成注入时间。
- 三列 trace 使用第一列作为 frontend 注入 cycle。
- `data=` 携带真实写 payload，`expect=` 或 `check=` 在读完成时比较 actual payload。
- `check=last_write` 使用 frontend 维护的地址级 golden map，逐地址检查最近一次写入的真实 payload。
- FR-FCFS 只重排独立地址；后到的重叠写必须等待更早的读完成，同地址 `R -> W`
  不允许读到未来数据。写合并遇到夹在中间的未完成读时会暂时反压 frontend。
- `expect=` 不匹配默认在输出统计后返回 3；只有显式使用
  `--allow-data-mismatch` 才把错误当作非致命统计。
- 空行和 `#` 注释会被忽略。

### 3.5 command trace 与验证

导出命令 trace：

```bash
./build/hbm_sim --standard hbm4 --requests 128 \
  --cmd-trace outputs/hbm4_cmd_trace.csv
```

导出并验证：

```bash
./build/hbm_sim --standard hbm4 --requests 128 \
  --cmd-trace outputs/hbm4_cmd_trace.csv \
  --validate-cmd-trace
```

CSV 字段：

```text
cycle,request_id,command,bus,channel,pseudo_channel,sid,rank,bank_group,bank,row,column
```

validator 会检查：

- 命令 bus 类型是否正确。
- HBM rising/falling edge 是否满足约束。
- HBM4 falling-edge `PREpb/PREab` 是否满足 edge pairing matrix。
- ACT/PRE/RD/WR/REF/RFM 是否满足 bank 状态。
- table-driven timing constraint 是否满足。
- tFAW 窗口是否满足。
- LPDDR WCK/CAS 窗口是否满足。

### 3.6 timing table 导出

```bash
./build/hbm_sim --standard hbm4 \
  --dump-timing-table outputs/hbm4_timing.csv
```

导出的 timing table 包含：

- 参数名。
- nCK 数值。
- timing 来源：`jedec`、`vendor`、`derived`、`research_default`。
- 是否仍需要 vendor 校准。
- 是否为当前模型必须字段。
- 注释说明。

### 3.7 DFI beat/signal trace

当前 DFI 分为在线 Behavioral PHY、beat-level 视图和 signal-like CSV 视图。它能表达训练/FIFO、命令周期、真实数据完成窗口、相位、地址、bank、payload 和 project-defined write mask，但还不是完整 DFI pin-level 协议。实现参考 DFI 6.0 公开功能类别并允许记录 6.0.1 目标标签；完整 lane 互连、模拟训练和错误/status sideband 仍需厂商 PHY profile 校准。

```bash
./build/hbm_sim --standard hbm4 --requests 8 \
  --cmd-trace outputs/hbm4_cmd_trace.csv \
  --dfi-trace outputs/hbm4_dfi_trace.csv \
  --dfi-signal-trace outputs/hbm4_dfi_signal.csv \
  --validate-dfi-trace \
  --dfi-phase-count 2 \
  --dfi-data-lane-bytes 16
```

beat CSV 字段包括 cycle、phase、kind、request_id、command、bus、beat、beat_count、beat_bytes、decoded 坐标、address、`issued_cycle`、payload_source、payload_initialized 和 payload_init_mask。signal CSV 在此基础上增加 `dfi_reset_n`、`dfi_cs_n`、`dfi_cke`、`dfi_odt`、`dfi_address`、`dfi_bank`、`dfi_rddata_en`、`dfi_wrdata_en`、`dfi_rddata_valid`、`dfi_wrdata`、`dfi_wrdata_mask`、`dfi_rddata` 等字段。`issued_cycle` 将 data beat 唯一关联回 RD/WR。`dfi_read_latency_nck` 默认使用 `nCL`，`dfi_write_latency_nck` 默认使用 `nCWL`。写数据 beat 的 `payload_source=request_payload`，读数据 beat 的 `payload_source=memory_image`；如果离线手工构造的 `IssuedCommand` 没有 payload 快照，则退回 `synthetic_fallback`，只用于协议窗口占位检查。

DFI 手册定义了 `dfi_wrdata_mask`/DBI 类总线，但具体极性取决于目标 memory signal 和模式；当前项目采用 project-defined active-high suppress 默认视图，不直接等同于项目内部 `MemoryImage` 的 write-enable mask。内部 mask 非零表示该 byte 被写入，导出到 `dfi_wrdata_mask` 时转成 `00`；内部 mask 为 0 表示该 byte 不更新，导出为 `ff`。精确 CA pin packing、lane/phase wiring、training、update、frequency-ratio change、low-power handshake 和厂商 PHY 私有结构仍未实现；这些部分需要后续依据 DFI 手册、HBM4/LPDDR6 JEDEC 手册以及目标厂商数据表继续补齐。

`--validate-dfi-trace` 通过时输出 `dfi_validation : PASS`，并给出 event、command、
data beat、latency、phase、signal、payload 和 expected payload 检查次数。validator
按 `request_id + command + issued_cycle` 建立索引；带 `expect=` 的读会独立比较实际
read beat。sequence tests 会故意破坏周期、payload、expectation 和 command enable。
DFI dump/validation 仍会保留完整命令、payload 和事件，应作为代表性调试窗口使用，
不作为百万请求满载性能实验的默认开关。

## 4. 配置用法详解

配置文件格式为：

```ini
key = value
```

加载顺序：

1. `--standard` 调用 `make_spec_draft(name)`，应用标准 traits 和默认 profile 选择。
2. 内置 profile 按 speed-bin、density、stack-height、mode 展开完整组织和 timing。
3. `timing_profile_file` 加载外部 profile 片段。
4. 主配置文件中的逐项覆盖生效。
5. 命令行参数最终覆盖配置文件。
6. `finalize_spec()` 一次生成 timing constraints/table。

### 4.1 标准选择

```bash
--standard hbm4
--standard hbm3
--standard lpddr6
--standard lpddr5
```

说明：

- `hbm4` 默认是 32-channel full-stack 研究配置。
- `hbm3` 默认是 16-channel stack-level baseline。
- `lpddr6` 是当前最新 LPDDR preset。
- `lpddr5` 用于 LPDDR5/LPDDR6 对比。
- `lpddr` 和 `ldppr` 会兼容映射到 `lpddr6`。

### 4.2 workload 参数

常用字段：

- `--pattern stream|random`：合成流量类型。
- `--trace PATH`：使用 trace 文件。
- `--requests N`：请求数量；trace 模式下 `0` 表示读完整 trace。
- `--read-ratio PERCENT`：读请求比例。
- `--seed N`：随机流量种子。
- `--addr-stride BYTES`：stream 地址步长。
- `--inject-interval N`：frontend 注入间隔。

### 4.3 controller 参数

常用字段：

- `--scheduler frfcfs|fcfs`：调度策略。
- `--row-policy open_page|closed_page|closed_cap`：行策略。
- `--row-policy-cap N`：ClosedCAP 访问上限。
- `--read-buffer-size N`：读队列容量。
- `--write-buffer-size N`：写队列容量。
- `--priority-buffer-size N`：维护请求队列容量。
- `--single-controller`：使用旧单 controller 模型。

含义：

- `FRFCFS` 会优先选择 row hit 和 timing-ready 请求，再按到达时间排序。
- `FCFS` 更接近简单先来先服务。
- `open_page` 保持行打开。
- `closed_page` 倾向使用 auto-precharge。
- `closed_cap` 在同一 bank 连续列访问达到 cap 后关闭行。

### 4.4 地址映射参数

常用字段：

- `--addr-mapping default|RoBaRaCoCh|ChRaBaRoCo|RoCoRaBaCh`
- `--channel-mapper decoded|round_robin|xor`

含义：

- `address_mapping` 控制地址 bit 如何拆成 row/bank/rank/channel/column。
- `channel_mapper=decoded` 使用地址解码结果。
- `round_robin` 按请求轮转 channel。
- `xor` 使用 cache-line 位异或分散 stream 流量。

### 4.5 timing/profile 参数

常用字段：

- `timing_profile`
- `timing_profile_file`
- `vendor_profile`
- `speed_bin_mbps`
- `density_gb`
- `stack_height`
- `mode_profile`
- `tCK_ps`
- `nCL`、`nCWL`、`nRCDRD`、`nRCDWR`、`nRP`、`nRAS`、`nRC`
- `tRFCab_ns`、`tRFCpb_ns`、`tRFCdb_ns`、`tREFI_us`

建议：

- 做真实器件校准时，不要直接相信 generic preset。
- JEDEC/vendor 表格片段优先放在 `configs/profiles/`。
- 开启 `--strict-timing-table` 可以检查当前 preset 是否仍含 vendor-required 默认值。

### 4.6 refresh/RFM 参数

常用字段：

- `--refresh-policy per_bank|all_bank`
- `--refresh-temperature normal|high|extended`
- `--refresh-postpone-limit N`
- `--refresh-pullin-limit N`
- `--refresh-credit-limit N`
- `--rfm-policy per_bank|all_bank`
- `--rfm-act-threshold N`
- `--rfm-decrement N`

含义：

- refresh manager 会生成 `REFpb`、`REFdb` 或 `REFab`。
- RFM manager 会按 ACT/RAA 计数触发 `RFMpb` 或 `RFMab`。
- postpone/pull-in/credit 用于研究 refresh deadline 和普通请求之间的仲裁压力。

### 4.7 HBM4 相关参数

常用字段：

- `hbm_full_32_channel_stack`
- `hbm_sid_interleave`
- `hbm_pc_interleave`
- `hbm_strict_edge_pairing`
- `hbm_edge_pairing_matrix`
- `hbm_sid_mapping`
- `hbm_ecc_scheme`
- `hbm_ras_policy`
- `hbm_link_crc_mode`
- `hbm_link_retry_enabled`
- `hbm_link_crc_bits_per_request`
- `hbm_ras_metadata_bits_per_request`
- `hbm_ecc_bits_per_request`

当前建模重点：

- 32-channel stack。
- pseudo-channel 和 SID 维度。
- row/column 双命令总线。
- rising/falling half-cycle 发射。
- PRE pairing 矩阵。
- RAS/ECC/link metadata 对接口占用的影响。

### 4.8 LPDDR6/LPDDR5 相关参数

常用字段：

- `lpddr_efficiency_mode`
- `lpddr_dvfs_mode`
- `lpddr_wck_mode`
- `lpddr_wck_ratio`
- `lpddr_mode_register_profile`
- `lpddr_wck_training_mode`
- `lpddr_dvfs_transition_policy`
- `lpddr_link_protection_mode`
- `lpddr_low_power_state_policy`
- `lpddr_link_protection`
- `lpddr_dbi_enabled`
- `lpddr_link_ecc_enabled`
- `lpddr_ca_parity_enabled`
- `low_power_mode`
- `low_power_entry_cycles`
- `low_power_exit_cycles`
- `self_refresh_exit_cycles`

当前建模重点：

- `ACT1 -> ACT2` split activate。
- `CAS_RD/CAS_WR -> RD/WR` WCK/CAS 行为。
- WCK sync/skip 统计。
- DVFS 后 WCK training debt。
- DBI/link ECC/CA parity 对接口开销的影响。
- power-down/self-refresh 的简化低功耗进入/退出。

## 5. 结果输出详解

输出采用固定宽度 `key : value` 格式，便于人工阅读和脚本解析。字段主要分为配置字段、验证字段和统计字段。

### 5.1 配置/标准字段

- `standard`：当前标准，如 HBM4、HBM3、LPDDR6。
- `timing_profile`：内置 timing profile 名称。
- `timing_profile_file`：外部 profile 文件路径；`off` 表示未使用。
- `vendor_profile`：vendor profile 标签。
- `mode_profile`：mode/timing 分支标签。
- `speed_bin_mbps`：速率档位，单位 Mbps/pin。
- `density_gb`：die density，单位 Gb。
- `stack_height`：堆叠层数；LPDDR 通常为 0。
- `dual_command_bus`：是否使用 HBM row/column 双命令总线。
- `split_activate`：是否使用 LPDDR split activate。
- `lpddr_family`：是否属于 LPDDR 系列。
- `data_rate_mbps`：接口数据速率。
- `data_bus_bits`：数据总线宽度。
- `prefetch_size`：预取长度。
- `tick_multiplier`：一个 nCK 被拆成多少 simulator tick。
- `tCK_ps`：时钟周期，单位 ps。
- `full_stack_model`：是否按 stack-level 模型运行。

### 5.2 协议能力字段

- `supports_refresh`：是否启用 refresh。
- `refresh_policy`：refresh 策略。
- `lpddr_dual_bank_refresh`：是否启用 LPDDR dual-bank refresh。
- `supports_rfm`：是否启用 RFM/PRAC。
- `rfm_policy`：RFM 策略。
- `supports_ecc`：是否启用 ECC 相关开销入口。
- `hbm_full_32ch_stack`：是否使用 HBM4 32-channel stack。
- `hbm_sid_interleave`：SID 是否参与 interleave。
- `hbm_pc_interleave`：pseudo-channel 是否参与 interleave。
- `hbm_edge_pairing`：是否启用 HBM edge pairing。
- `hbm_strict_edge_pairing`：是否使用严格 pairing 检查。
- `hbm_pairing_matrix`：当前 HBM pairing 规则名称。
- `hbm_sid_mapping`：SID 映射策略名称。
- `hbm_ecc_scheme`：ECC 建模策略名称。
- `hbm_ras_policy`：RAS 策略名称。
- `hbm_link_crc_mode`：HBM link CRC 模式。
- `hbm_link_retry`：是否启用 link retry 入口。
- `lpddr_link_protection`：是否启用 LPDDR link protection。
- `lpddr_efficiency_mode`：LPDDR efficiency mode。
- `lpddr_dvfs_mode`：LPDDR DVFS mode。
- `lpddr_wck_mode`：WCK 模式。
- `lpddr_wck_ratio`：WCK 与 CK 的比率。
- `lpddr_mr_profile`：mode register profile 名称。
- `lpddr_wck_training`：WCK training policy。
- `lpddr_dvfs_policy`：DVFS transition policy。
- `lpddr_link_mode`：link protection mode。
- `lpddr_low_power_policy`：低功耗策略名。

### 5.3 timing table 字段

- `timing_table_entries`：当前 timing table 表项数量。
- `timing_vendor_required`：需要 vendor 数值校准的字段数量。
- `timing_source_jedec`：来源为 JEDEC 的字段数量。
- `timing_source_vendor`：来源为 vendor 的字段数量。
- `timing_source_derived`：公式推导字段数量。
- `timing_source_research`：研究默认值字段数量。
- `timing_vendor_required_only`：仍然只靠 vendor-required 默认值支撑的字段数量。
- `timing_table_dump`：timing table dump 路径；`off` 表示未导出。

### 5.4 command trace validation 字段

- `cmd_trace`：命令 trace 输出路径。
- `cmd_validation`：`off`、`pass` 或失败描述。
- `cmd_validation_checked`：validator 检查的命令数量。
- `cmd_validation_bus_checks`：bus 类型检查次数。
- `cmd_validation_edge_checks`：HBM edge 检查次数。
- `cmd_validation_pair_checks`：HBM4 PRE pairing 检查次数。
- `cmd_validation_state_checks`：命令状态合法性检查次数。
- `cmd_validation_timing_checks`：timing constraint 检查次数。
- `cmd_validation_timing_updates`：timing 状态更新次数。
- `cmd_validation_faw_events`：tFAW 窗口事件数量。
- `cmd_validation_wck_checks`：LPDDR WCK 窗口检查次数。

### 5.5 workload 与组织字段

- `memory_system`：`multi_controller` 或 `single_controller`。
- `scheduler`：调度器。
- `row_policy`：行策略。
- `row_policy_cap`：ClosedCAP 上限。
- `address_mapping`：地址映射模板。
- `channel_mapper`：channel 分发策略。
- `inject_interval`：请求注入间隔。
- `init_sequence`：初始化/训练序列。
- `init_sequence_interval`：控制序列注入间隔。
- `read_buffer_size`：读队列容量。
- `write_buffer_size`：写队列容量。
- `line_size`：frontend/host 默认请求粒度，单位 byte；HBM4 和 LPDDR6 当前为 64B。
- `dram_transaction_bytes`：一条 RD/WR 命令和 MemoryBackend 块的 payload
  粒度；HBM4 x32/BL8 和 LPDDR6 x12/BL24 当前均为 32B，因此默认 64B host
  请求拆成两个物理事务。
- `channels`：channel 数。
- `pseudo_channels`：pseudo-channel 数。
- `sids`：SID 数。
- `banks`：总 bank 数。

### 5.6 基础完成情况字段

- `cycles`：仿真用到的 controller cycle 或 system cycle 基准。
- `reads`：注入的读请求数量。
- `writes`：注入的写请求数量。
- `completed_reads`：完成的读请求数量。
- `completed_writes`：完成的写请求数量。
- `row_hits`：行命中次数。
- `row_misses`：行未命中次数。
- `row_conflicts`：行冲突次数。

判断一次实验是否有效，至少要同时看：

- `completed_reads + completed_writes`
- `remaining_requests`
- `remaining_pending`
- `hit_cycle_limit`

如果 `hit_cycle_limit=true`，说明仿真到达 `--max-cycles` 仍未完成，带宽和延迟可能不能代表完整 workload。

### 5.7 命令计数字段

- `commands.ACT`：HBM/通用 activate。
- `commands.ACT1`、`commands.ACT2`：LPDDR split activate。
- `commands.PRE`：普通 precharge。
- `commands.PREpb`：per-bank precharge。
- `commands.PREab`：all-bank precharge。
- `commands.CAS_RD`、`commands.CAS_WR`：LPDDR CAS/WCK sync 阶段。
- `commands.RD`、`commands.WR`：普通读写。
- `commands.RDA`、`commands.WRA`：带 auto-precharge 的读写。
- `commands.REFab`、`commands.REFpb`、`commands.REFdb`：all-bank/per-bank/dual-bank refresh。
- `commands.RFMab`、`commands.RFMpb`：all-bank/per-bank RFM。
- `commands.MRW`、`commands.MRR`：mode register write/read。
- `commands.WCK_SYNC`、`commands.WCK_TRAIN`：WCK 同步/训练。
- `commands.DVFS`：DVFS transition。
- `commands.PDE`、`commands.PDX`：power-down enter/exit。
- `commands.SREFEN`、`commands.SREFEX`：self-refresh enter/exit。
- `commands.ECC_SCRUB`：ECC scrub 抽象命令。
- `commands.RAS_ERR`：RAS/error 抽象事件。

### 5.8 refresh/RFM/调度事件字段

- `maintenance_requests`：进入 priority path 的维护请求数量。
- `maintenance_served`：实际发出的维护请求数量。
- `refresh_batches`：refresh 批次数。
- `refresh_pb_batches`：per-bank refresh 批次数。
- `refresh_ab_batches`：all-bank refresh 批次数。
- `refresh_postpones`：refresh 延后次数。
- `refresh_pullins`：refresh 提前次数。
- `refresh_credit_peak`：refresh credit 峰值。
- `rfm_events`：RFM 事件总数。
- `rfm_pb_events`：per-bank RFM 事件。
- `rfm_ab_events`：all-bank RFM 事件。
- `rfm_decrements`：RFM 后 RAA 计数递减次数。
- `dual_issue_cycles`：HBM row/column 双发射 cycle 数。
- `row_bus_issues`：row bus 发射次数。
- `column_bus_issues`：column bus 发射次数。
- `unified_bus_issues`：统一命令总线发射次数。
- `rising_edge_ticks`、`falling_edge_ticks`：HBM half-cycle tick 统计。
- `write_mode_cycles`：write-drain 模式持续 cycle。
- `injected_requests`：frontend 成功注入请求数。
- `injection_stall_cycles`：队列满导致注入停顿的 cycle。
- `read_forwards`：读命中写缓冲并 forward 的次数。
- `write_coalesces`：同地址写合并次数。
- `row_policy_ap_upgrades`：row policy 将 RD/WR 升级为 RDA/WRA 的次数。
- `row_policy_precharges`：row policy 注入 PRE 的次数。

### 5.9 LPDDR/HBM 链路与低功耗字段

- `wck_syncs`：WCK/CAS 同步次数。
- `wck_sync_skips`：WCK 窗口内跳过重复 CAS 的次数。
- `wck_training_events`：WCK training 事件数。
- `mode_register_ops`：MRW/MRR 操作数。
- `dvfs_transitions`：DVFS transition 数。
- `ras_ecc_events`：RAS/ECC 抽象事件数。
- `act2_deadline_forced`：ACT2 deadline 强制调度次数。
- `low_power_entries`：进入低功耗次数。
- `low_power_exits`：退出低功耗次数。
- `low_power_cycles`：低功耗驻留 cycle。
- `low_power_exit_blocked`：低功耗退出阻塞 cycle。
- `interface_command_bits`：命令/地址侧额外接口 bit，例如 CA parity。
- `interface_overhead_bits`：总接口额外 bit，包括 ECC/DBI/CRC/metadata 等。

### 5.10 system/controller 分层字段

- `controller_count`：controller 总数，通常等于 channel 数。
- `active_controllers`：实际处理过请求的 controller 数。
- `system_cycles`：memory system 全局 cycle。
- `aggregate_ctrl_cycles`：所有 controller cycle 之和。

注意：

- 多 controller 模式下，`system_cycles` 表示并行推进的全局时间。
- `aggregate_ctrl_cycles` 表示所有 controller 的总工作量口径。
- 做带宽对比通常看 `system_cycles`。
- 做平均队列压力或 controller 聚合分析可看 `aggregate_ctrl_cycles`。

### 5.11 带宽字段

- `read_bytes`：完成读 payload 字节。
- `write_bytes`：完成写 payload 字节。
- `interface_read_bytes`：包含协议开销后的读接口字节。
- `interface_write_bytes`：包含协议开销后的写接口字节。
- `if_xfer_rate_Gbps`：接口传输速率，单位 Gbps/pin 或等效 link 速率。
- `peak_bandwidth_GBps`：理论峰值带宽。
- `achieved_bw_GBps`：payload 实际带宽。
- `achieved_if_bw_GBps`：包含接口开销后的接口实际带宽。
- `bandwidth_util_pct`：payload 带宽利用率。
- `payload_efficiency_pct`：payload / interface 的有效载荷效率。

典型判断：

- `achieved_bw_GBps` 高但 `payload_efficiency_pct` 低，说明协议/ECC/DBI/CRC/metadata 开销较大。
- `active_controllers` 很低时，stream 可能集中在少数 channel，需要检查 `channel_mapper` 和地址映射。
- `bandwidth_util_pct` 很低但队列很长，可能是 timing、refresh/RFM 或 row conflict 限制。

### 5.12 延迟和队列字段

- `avg_read_latency`：平均读延迟。
- `read_queue_len_avg`：读队列平均长度。
- `write_queue_len_avg`：写队列平均长度。
- `priority_queue_avg`：维护请求队列平均长度。
- `active_queue_len_avg`：active buffer 平均长度。
- `read_q_avg_per_ctrl`：每 controller 平均读队列长度。
- `write_q_avg_per_ctrl`：每 controller 平均写队列长度。
- `priority_q_avg_per_ctrl`：每 controller 平均维护队列长度。
- `active_q_avg_per_ctrl`：每 controller 平均 active buffer 长度。
- `read_bytes_per_cycle`：每 cycle 读字节。
- `write_bytes_per_cycle`：每 cycle 写字节。
- `total_bytes_per_cycle`：每 cycle 总 payload 字节。

### 6.10 源码：core

- `src/core/data.cpp`：真实存储区语义实现。通过 `MemoryBackend` 保存 cache-line payload/init/meta，支持 txt load、txt/CSV/binary dump、binary load、逐 byte init mask 读取、masked write、bank/row/column/tile/grid/subarray/mat/cell/microbump 映射、SECDED shadow、错误注入/纠错统计，以及 TSV-aware 稀疏 3D RC 热耦合。
- `src/core/memory_backend.cpp`：payload 后端实现。提供 `sparse`、`mmap_sparse`、`chunk_file` 三种保存方式，用于 debug、较大工作集和满容量写入场景。

- `src/dram/standard_traits.cpp`：标准 traits 目录。保存名称/别名、协议族、能力、

- `src/dram/profiles.cpp`：organization/timing profile 展开实现。根据 speed-bin、
  density、stack-height、mode、vendor 生成完整 HBM/LPDDR 数值并加载外部 profile。
- `src/dram/spec.cpp`：统一 `make_spec(name)`、timing table、constraints 和

- `src/dram/jedec.cpp`：JEDEC 单位换算实现。把 ns/us/ps 和 JEDEC 公式转换为 nCK。
- `src/dram/semantics.cpp`：命令语义表实现。定义每条命令的 bus、scope、类别、是否 row/column/maintenance/control、是否 all-bank 等属性。
- `src/dram/state.cpp`：命令合法性状态机实现。检查 ACT/PRE/RD/WR/REF/RFM/MR/WCK/DVFS/低功耗命令是否满足当前状态。
- `src/dram/interface.cpp`：接口开销模型实现。计算 request-level 和 command-level 的 ECC、DBI、CRC、metadata、CA parity 等 overhead。
- `src/dram/README.md`：dram 源码目录说明。

### 6.12 源码：controller

- `src/controller/controller.cpp`：controller 协调层实现。维护 read/write/active/priority buffer，执行请求生命周期，选择命令，处理 HBM row/column 双发射、HBM edge pairing、LPDDR split activate、低功耗进出和统计更新。
- `src/controller/executor.cpp`：命令副作用实现。执行 ACT/PRE/RD/WR/RDA/WRA/REF/RFM/MR/WCK/DVFS 等命令对 bank 状态、timing、统计、RFM 计数的影响。
- `src/controller/timing.cpp`：timing engine 实现。维护 scope-level ready cycle、tFAW 窗口、WCK active window、table-driven timing constraint。
- `src/controller/scheduler.cpp`：调度策略实现。实现 FRFCFS 和 FCFS 的候选选择逻辑。
- `src/controller/row_policy.cpp`：行策略实现。实现 open-page、closed-page、ClosedCAP 下的 auto-precharge 升级和显式 PREpb 注入判断。
- `src/controller/refresh.cpp`：refresh manager 实现。生成 per-bank/all-bank/dual-bank refresh 请求，维护 refresh interval、postpone、pull-in 和 credit。
- `src/controller/rfm.cpp`：RFM manager 实现。维护 ACT 计数阈值、生成 RFMpb/RFMab，并在 RFM 后递减计数。
- `src/controller/README.md`：controller 源码目录说明。

### 6.13 源码：frontend

- `src/frontend/traffic.cpp`：请求前端实现。生成 stream/random workload，流式读取 trace，展开 `BW/BR` burst，处理 `data=`、`expect=`、`mask=`、`check=last_write`，并生成 HBM/LPDDR 初始化、训练、DVFS、低功耗、RAS/ECC 控制序列。
- `src/frontend/README.md`：frontend 源码目录说明。

### 6.14 源码：stats

- `src/stats/stats.cpp`：统计输出实现。按稳定顺序打印 `Stats` 字段，使用统一宽度对齐 `key : value`，并输出带宽、利用率、队列平均值等派生指标。
- `src/stats/README.md`：stats 源码目录说明。

### 6.15 源码：validation

- `src/validation/dfi.cpp`：DFI beat/signal trace 生成器和 validator。除 CSV 导出外，还检查 command/data 事件配对、beat、phase、latency、signal、payload/source/init/write-mask。

## 8. 当前模型边界

当前项目已经具备 HBM/LPDDR 控制器研究的小型标准化模拟器骨架，但仍有明确边界：

- timing table 不是完整官方 JEDEC/vendor 全表，仍有研究默认值。
- HBM4 的 RAS/ECC/link retry/training 仍是结构化入口，不是完整错误注入和修正流程。
- LPDDR6 的 mode register bit-level 语义、完整 WCK training、运行时多频点 DVFS 和低功耗状态图仍可继续深化。
- power 模型目前偏轻量，重点仍是带宽、时序、命令行为和接口开销。
- 固定 HBM4 8000 单 channel 共同命令面已完成 Ramulator2.1 外部参考检查，周期差在已解释的 2 tick 粒度内。该检查不覆盖也不裁决真实 payload、memory backend、full-stack、DFI、功耗/热和来源治理；这些由项目原生测试与 `project_identity.csv` 约束。

因此，使用本项目做论文或工程数值对比时，建议明确写出：

- 使用的配置文件。
- timing profile 来源。
- 是否启用 strict timing table。
- 是否使用 command trace validation。
- 是否使用 DFI validation，以及 Ramulator2.1 差分是否运行。
- 地址映射、channel mapper、scheduler、row policy。
- refresh/RFM 策略。
- ECC/DBI/CRC/metadata overhead 假设。

这样可以保证实验可复现，也能清楚区分“已经按手册/厂商表校准的部分”和“仍属于研究假设的部分”。
