# 统计输出精简验收

## 本轮范围

按用户确认的“模型、必要参数、性能结果”三部分实施，不修改调度、时序判定、
请求数据路径或热模型计算公式。保留工作区前一轮配置重构及用户已有修改。

- summary/full 合并为精简人读报告，HBM4 示例约 28 行。
- JSON schema 2 分为 model、parameters、metrics、validation、changes、stacks。
- 该 HBM4 示例公共 metrics 为 21 项；修改前 schema 1 的平铺集合为 442 项，
  后者混有配置、路径和诊断，不能宣称删除了 421 个独立性能计数器。
- 公共结果集合真正缩减；只有显式 diagnostic 才导出内部审计字段。
- 取消七个重复派生项及其 C++ 辅助函数：三项 bytes/cycle、四项全局队列均值。
  保留有验证用途的命令、维护、PHY、后端原始计数，不以输出精简为由破坏测试。
- 删除性能曲线、敏感性及架构扫描中不再使用的三个文本解析器。
- 性能曲线用一个 row_hit_pct 替代三项行访问计数；曲线产物版本为 2。
- 敏感性分析关闭功耗/热时不再生成伪零测量，产物版本为 2。
- C++ 类型化结果直接序列化，64 位计数不经过 double，JSON 不继承终端舍入。
- 参数变化对比当前程序内置同标准基准；直接修改标准段也会识别。
  Timing 来源标签不冒充数值变化；power.source 切换计算公式则必须记为变化。

接口和字段完整定义见 [结果输出与实验有效性](结果输出与实验有效性.md)。
主手册、使用手册、项目指南、构建流程和相关目录 README 已同步。
详细查验命令改为 diagnostic；普通可视化/Demo 改读 JSON。历史验收记录加版本提示，
不把前一轮测试结果追写成这一轮结果。

结果契约还覆盖：纯写时读延迟 null、关闭模块不生成测量值、行命中率分母、
多实例统计汇总、直接改 HBM3 columns 后容量及 density 联动、诊断显式选择、
历史文本/schema 1 读取、错误路径和输入保护、截断及数据/Golden 不匹配。

回归中发现并修复的适配问题没有通过放宽数值门限解决：

1. 可视化和 Demo 原先解析人读 stdout，改为读取 JSON。
2. 专项 smoke/外部对照依赖内部键，改为显式 diagnostic。
3. 原敏感性工具把关闭模块的诊断零值作为测量，改为缺省，不补零。
4. 原 full 文本的舍入会掩盖 double 原始精度，比较时区分整数精确性和旧浮点显示精度。

## 使用与边界

```bash
./build-clang-debug/hbm_sim --config configs/hbm.cfg --standard hbm4 \
  --requests 128 --stats-json outputs/compact_run/result.json
python3 tools/view_stats.py outputs/compact_run/result.json \
  --keys standard,simulation_time_ns,achieved_bw_GBps,avg_read_latency_ns
```

命令行可不指定 stats view；旧 full 参数仍接受，但不再输出旧的数百行键。
需要 PHY/后端/响应队列等内部诊断时使用 `--stats-view diagnostic`。
未知或未收集指标不能视为零；无独立数据检查不能称为数据验证通过。

这些结果证明本轮输出重构的回归情况，不证明任意配置绝无错误，不构成厂商器件校准。
可视化本轮验证了数据读取与 HTML 生成，未将其宣称为所有浏览器的交互验收。
