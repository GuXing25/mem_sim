# 配置、参数联动与迁移

## 1. 用户操作方式

普通用户只需两份主模板：`configs/hbm.cfg`、`configs/lpddr.cfg`。复制其中一份，选择
`[model] base_standard`，修改对应 `[standard.<协议>.organization]`、功能 section 或
`[override]`，即可单独运行。无需 developer.cfg，也无需先注册自定义型号名称。

```bash
mkdir -p experiments/local outputs/config_demo
cp configs/hbm.cfg experiments/local/my_geometry.cfg
# 用编辑器修改副本：base_standard=hbm3，将 HBM3 的 columns 从32改为16。
# 只修改副本，不修改原模板。
./build-clang-debug/hbm_sim --config experiments/local/my_geometry.cfg \
  --check-config --explain-config \
  --dump-resolved-config outputs/config_demo/resolved.cfg
./build-clang-debug/hbm_sim --config experiments/local/my_geometry.cfg \
  --requests 128 --validate-cmd-trace --validate-dfi-trace \
  --stats-json outputs/config_demo/result.json
python3 tools/view_stats.py outputs/config_demo/result.json \
  --keys standard,density_gb,aggregate_capacity_bytes,system_cycles,remaining_requests,hit_cycle_limit
```

`cp` 目标如果已经存在会覆盖，请给新的实验副本取新名字。以上是两次独立执行：第一次只检查，
第二次仿真；不会继承上次进程内状态。命令行覆盖配置文件，`--standard` 覆盖 `base_standard`。

模板不是必须填写的完整字段清单：未填写的独立参数采用 C++ 协议基准，未填写的联动项按下表
计算；所有已实现的高级覆盖键仍可使用。完整生效值用 resolved 文件查看，不要从短模板猜测。

## 2. 三类参数

| 类别 | 例子 | 使用原则 |
|---|---|---|
| 主输入/独立控制 | 几何维度、接口速率、队列大小、scheduler、row_policy、backend、PHY、ECC、功耗/热系数 | 修改会作用于对应模型；算法必须已有实现 |
| 有明确依赖的派生值 | CK、speed selector、几何密度、默认接口总宽度；有条件联动的 nRC/RFM | 通常省略；显式值与规则矛盾时拒绝，不能同时维护两套真值 |
| 审计身份 | model_name、timing_profile、vendor_profile、mode_profile、DFI 版本名称 | 名称本身不会生成实现或证明厂商校准，不再通过名称子串打开保护/效率模式 |

来源标签 `timing_override_source` 影响可信度检查，不改变时序数值。新覆盖默认标记为
`research_default`；把 vendor_profile 改成厂家名称不会使内置默认值变成 vendor 数据。
用户显式声明 vendor/JEDEC 来源仍需真实资料支撑，程序不能自动证明声明真实性。

## 3. schema 3 的确定规则

设每实例几何容量为 C，事务字节数为 T：

```text
C = channels × pseudo_channels × sids × ranks
    × bank_groups × banks_per_group × rows × columns × T
系统总容量 = C × stack_count
```

`columns` 是事务地址槽数，不是 DRAM 引脚原始列地址数；不能再乘 prefetch、总 DQ 宽度或
stack_height。HBM 的 ranks=1 是统一地址模型占位层，SID 不是一个 die；本式是逻辑地址空间，
不唯一确定 die/channel 的物理分配。

| 省略或 auto 的键 | 派生规则 |
|---|---|
| `data_rate_mbps` | 优先使用显式 speed_bin，否则协议基准；LPDDR6 low 模式取 low_data_rate |
| `speed_bin_mbps` | 等于最终 data_rate_mbps，不再另设相互冲突的速率 |
| `tCK_ps` | HBM：4,000,000 / rate；LPDDR：2,000,000 × WCK:CK / rate |
| `density_gb` | HBM：C×8/2^30/stack_height；LPDDR：C×8/2^30/(channels×subchannels×ranks) |
| `data_bus_bits` | channels×PC×所选基准每 PC/subchannel 的 DQ 位宽；允许显式研究覆盖 |

密度单位是 Gibit（2^30 bit）；可为小数。LPDDR5 基准 PC=1，LPDDR6 基准 PC=2。
改 stack_height 不会偷偷增减 SID，也不会自动扩大逻辑容量。
这里只能按等容量 die 或子通道估算密度，缩成一个通道的验证实例不能自动当作完整物理 die。

HBM3 模板容量16 GiB/Stack、每 die16 Gibit；columns=16 后变为8 GiB/Stack、每 die8 Gibit。
HBM4 模板32 GiB/Stack、每 die32 Gibit。后端 `capacity_bytes=0` 跟随几何容量；文件逻辑长度、
实际分配磁盘块和内存缓存占用仍是不同概念。显式小后端容量不会自动缩小随机流量地址范围。

LPDDR5 支持 WCK:CK=2或4；LPDDR6 按 JESD209-6 为2。内部 tick 时长为 CK/tick_multiplier。
CK 在任何 ns/us→nCK 换算之前确定，以向上取整得到约束。显式 CK 仅接受小于等于0.5 ps 的
数值舍入差，不可把独立修改时钟当作已经校准另一种接口速率。

### Timing 的联动边界

- 修改 nRAS 或 nRP，且没有显式 nRC 时，重新计算 nRC=nRAS+nRP；不修改主项则保留基准 nRC。
- 除 LPDDR6 外，修改 nRFC/nRFCpb 且没有显式 RFM 恢复值时，按项目默认关系同步 nRFMab/nRFMpb。该等式不是
  任意器件 RFM 参数的保证；有资料或独立实验时请显式给出 RFM 值。
- LPDDR6 的 RFM 按 JESD209-6 第396页表366/367独立计算：5×80 ns=400 ns、5×70 ns=350 ns，
  不随 nRFC/nRFCpb 的密度档或研究覆盖变化；显式 nRFMab/nRFMpb 仍可覆盖该基准。
- DFI read/write latency 为0表示运行时跟随当前 RL/WL；显式正值仍是独立接口覆盖。
- 同一时序只能选择一个拼写/单位，例如 nRP 或 tRP_ns；schema 3 同时填写会拒绝，避免行顺序
  决定结果。上层 CLI 如需覆盖，请使用同一个键。
- 其他时序仍可独立覆盖；不能因为数学上可能相关就自动改动 nCL、nCWL、nFAW 等实验输入。
- 派生值会继承尚未解决的来源缺口：对研究参数做加法，不会自动得到已校准时序。

未知调度器、错误协议字段、非正几何维度、容量乘法溢出、矛盾密度/速率均报错，不静默替换成
默认策略。但检查通过不等于所有参数组合都有 JEDEC 或器件依据，也不能证明不存在运行时 bug。

## 4. 与 Ramulator 的关系

采用接近 Ramulator 的职责分层，而不是把本项目替换成 Ramulator 或兼容其 YAML：

```text
配置文档与合并 → 模型构建/参数推导 → 生效配置
Frontend（请求产生、接收背压）
  → MemorySystem（拆分、路由、响应聚合）
    → Controller（队列、调度器、行策略、刷新）
      → MemPhy/协议适配 → MemoryImage/数据后端
Stats/trace 在各阶段采集，不是数据必须穿过的串行模块。
```

可复用的模型构建接口在 `include/hbm_sim/config/model.hpp` / `src/config/model.cpp`。
Frontend 保留带 payload/byte mask 的变长突发和异步响应；Controller 的策略仍为 fcfs/frfcfs，
不能填写陌生名称自动生成实现。共同 FRFCFS 发射选择用独立候选集测试对照本地 Ramulator，
不额外把普通 FRFCFS 解释为 row-hit-first。保留本项目数据/ECC、完成响应、PHY、后端和热扩展，
因此完整轨迹和响应时点不承诺与 Ramulator 完全相同。

## 5. 版本迁移和数值变化

新主模板使用 schema 3。schema 1/2 保留显式覆盖语义；四份内部单通道验证配置固定 schema 2，
不让通道缩减触发物理密度重算。它们是测试夹具，不是用户必须叠加的配置。
`--dump-resolved-config` 输出 schema 2 的完整显式快照及派生公式注释，以便重放实际参数；
历史 resolved 文件仍按旧语义载入。旧 timing_profile_file 仅在 schema 1/2 使用，新模型使用内联覆盖。

去掉冗余表前已比较 C++ 基准与主模板，并将 HBM3/LPDDR5 的外部参考参数合入协议基准，
明确标 external_reference，不把它们升级为 JEDEC 厂商表。HBM3 的8 nCK nRREFD 属于此参考口径。

LPDDR6 有单独的语义修正，不属于纯格式迁移：

- WCK:CK=2；刷新按 JESD209-6 第282页表302的**两个 subchannel 合计密度**查表。
  16 Gibit/subchannel 对应32 Gibit，采用380/210 ns；不存在或 TBD 的密度标为研究替代。
- RFM 从原先复制 RFC 改为表366/367独立的400/350 ns，经最终 CK 向上取整。刷新密度缺口
  不会降级这两项独立公式的来源；完整 PRAC/ABO 器件行为仍不由这两个时序值证明。
- RP 保留 nACU 与时间项的向上取整；RTP 保留 burst 占用及 tail。旧模板的手填123/132、RTP=4
  不再覆盖协议函数结果。10667 Mb/s 对应精确 CK≈374.988 ps，部分整数 timing 因此增加1 nCK。
- 训练、控制恢复研究参数不再伪标 JEDEC。默认 exploratory 可运行，不再声称默认表通过严格器件校准。

HBM4 刷新也已按 JESD270-4A 第195–196页表108修正：24 Gibit/die 的4/8/12/16Hi
RFCab分别为360/410/450/490 ns，32 Gibit/die分别为400/450/490/530 ns；RFCpb分别为
240/280 ns。不再用一个密度阈值忽略 stack_height。其他密度/高度仍可研究，但替代值明确标
research_default；项目 RFM恢复默认复制RFC也不冒充器件RFM证据。HBM3非表列密度/高度同样
不再因落入阈值区间就标JEDEC。实际密度由主输入几何推导，不由型号名称决定。

迁移阶段64 Host请求的对照：HBM3/HBM4/LPDDR5分别205/219/576 tick保持一致；LPDDR6从1621到
1623 tick。命令与DFI检查均通过；这是小用例回归，不是全面的物理准确度验证。历史输出不覆盖。

## 6. 结果与验收

默认终端 summary 只展示关键字段；诊断用 `--stats-view diagnostic`。程序分析使用完整
`--stats-json`，不能依赖终端字段总是存在。工具拒绝缺失必需指标、未完成/失败运行，不把缺字段填0。
详见[结果输出与实验有效性](结果输出与实验有效性.md)。

实验至少检查 exit code、run_status、remaining_requests、hit_cycle_limit、请求/事务/响应数，
以及本实验要求的命令、DFI、数据验证。data_mismatches=0而data_checked_reads=0不证明数据正确。
策略/几何改变后先做小请求和带独立 expect 的读写回归，再做压力曲线。运行用新的输出目录。
